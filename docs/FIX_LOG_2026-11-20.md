# FIX_LOG 2026-11-20

## F1 定时任务自 2026-11-08 起每天失败（用户收到的失败邮件来源）

### 现象

`Refresh AI compute dashboard` 的 `schedule` 任务从 `2026-11-08` 起连续 13 次失败（11-08 → 11-20），每失败一次 GitHub 发一封邮件，这就是最近的告警邮件来源。

失败步骤每天都固定是最后一道门 `Validate dashboard (full test suite)`；`Refresh source data and build site`、`Validate deploy freshness`、`Browser smoke test`（40 项全绿）都通过，所以数据抓取本身没坏。

唯一失败用例：

```
test_suite/test_gpu_external.py::test_crosscheck_h100_and_a100_rules
assert h100["diff_pct"] == pytest.approx(-8.4, abs=0.01)
E   assert -12.09 == -8.4 ± 0.01          # 2026-11-20
E   assert -6.93 == -8.4 ± 0.01           # 2026-11-08（首次失败）
```

### 根因

断言把 **2026-11-04 那一天的行情结果**写死了。workflow 的顺序是「先抓真实价格 → 再跑测试」，所以测试看到的是当天新采集的自有面板；`diff_pct = own_median / ext_median - 1`，而 external 是已提交的冻结快照（`2026-11-03`，`h100` median `3.97`），只有 own median 每天在动：

| 日期 | own H100 on-demand median | own 家数 | diff_pct |
|---|---|---:|---:|
| 2026-11-04 | 3.63645（实测，当日 FIX_LOG 记录） | 24 | -8.4% |
| 2026-11-08 | ≈3.695（按 ext_median=3.97 反算） | 24 | -6.93% |
| 2026-11-20 | ≈3.490（按 ext_median=3.97 反算） | 24 | -12.09% |

11-08 与 11-20 的 own median 是我按 `diff_pct = own/ext - 1` 反算的区间值（未留存当日原始 median），只用于说明漂移方向与量级。

口径没有问题，是断言在锁某一天的数值。同类写死值还有 `overlap_count_match == 3`、`GH200 own_providers == 3`、`RTX 4090/5090 own_providers == 4`——provider 一进一出就会同样炸。

### 连带影响（比邮件本身严重）

失败点在 `Commit refreshed artifacts` **之前**，所以从 11-08 起数据从未提交过：`main` 上最后一份产物停在 `2026-10-31`（自有面板截至 `2026-10-29`），对外站点数据已 22 天未更新。也就是说邮件刷屏的背后是「刷新链路整体停摆」。

## 修复内容

1. `diff_pct` 只锁恒等式：`round(own_median / ext_median - 1, 2)`；保留「官方 `rate_card_median` 只作审计、绝不进 diff」的口径检查（两者不相等时，`diff_pct` 必须不等于 published 口径的结果）。
2. 其他写死值收口为规则：`overlap_count_match == 3` → `1 <= match <= overlap_count`；`GH200`/`RTX 4090`/`RTX 5090` 的 `own_providers == 3/4` → `0 < n < CROSSCHECK_MIN_OWN_PROVIDERS`，锁「样本薄 → 不给差值」的规则，不锁具体家数。
3. 新增 `test_crosscheck_rows_are_price_drift_safe`：对全部 66 行校验口径恒等式——`own_thin` 与 8 家闸门一致、`comparable` 蕴含 `diff_pct` 非空且 `coverage ∈ {ok, mixed}`、非 `comparable` 一律无 diff、diff 只能来自 `ext_median`、overlap 结构自洽、`benchmark_id/ext_benchmark_median` 只出现在 `on_demand`。
4. 前提断言带诊断信息：own 样本真的跌破 8 家时，报「own 样本跌破门槛」并打印整行，而不是伪装成数字不符。
