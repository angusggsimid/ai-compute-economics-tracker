### B. 架构

- 共享 shell：`html_dashboard/site_shell.py` 提供 `page(title, description, base, active, body, script)` 与 `NAV`，统一生成 topbar、导航、main、footer；根页 `base="."`，`gpu/`、`providers/` 页 `base=".."`。
- 共享资源：`public/assets/site.css` 沿用现有 Apple-like 配色和字号，`site.js` 暴露 `window.CC`（fetch、格式化、表格、筛选、SVG 折线图、导航）。无 CDN、无第三方运行时依赖。
- 数据访问：页面不内嵌数据，只通过 `CC.get()` fetch `public/data/*`；`<body data-base>` 让所有资源、页面链接和数据请求都用相对路径，支持 GitHub Pages 子路径部署，源码与生成物中不存在 `"/data/...` 绝对路径。
- 模块拆分：`site_data.py` 生成切片；`site_landscape.py` 生成 landscape/providers；`site_detail.py` 生成卡页/provider 页；`site_tools.py` 生成 compare/spread/cheapest；`site_build.py` 统一清理、写资源、写页面。
- 构建链路：`write_public_data()` 写完 P2-2 数据后调用 `write_site_data(public_dir, full, external)`；`main()` 再调用 `write_site(PUBLIC_DIR)`。当前输出 `site={count:176, pages:174, assets:2}`。自定义 `out_dir` 时，`write_public_data(out_dir)` 只写数据并补齐 `out_dir/data` 的 `prices.json`、`crosscheck.json`、`gpus.json`、`providers.json`、`site-index.json` 等运行切片；页面必须再调用 `write_site(out_dir)` 生成，完成后 staging 页面才可直接 fetch。
- 导航与发布：`public/index.html` 顶栏和移动导航新增“数据页 → landscape.html”；主页面 favicon 在最终 build 中移除 `data:,` 空图标，只保留相对 `./favicon.svg`。`.github/workflows/refresh-dashboard.yml` 的 `git add` 改为覆盖整个 `public`，新页面、assets 和数据切片会一起提交。
- 运行前提：所有页面依赖静态 HTTP fetch；`file://` 直接打开会显示数据加载失败，与现有 crosscheck 行为一致。

### D. 页面行为

- **Landscape**：66 行（11 卡 × 6 market），列含 GPU、market、own median、P25–P75、cheapest、own N、7d、weekly index、external median、coverage、状态；支持卡、market、coverage、搜索筛选；每行链接到 `gpu/<slug>.html`。0 家自有 provider 的 market 显示“无自有报价”；Weekly idx 只对 on-demand 显示。
- **Providers**：158 行（37 own + 121 外部）。外部行标 `gpueconomy`，同时显示 `Live coverage`、`Live quotes` 和 raw 记录数；Live coverage 拆成 own key cards / ext GPU ids，两者单位不同、不可直接比较；live 口径为 `status=live`、非 `marketplace_floor`、`listed_currency=USD`。Edgevana 显示 `0 live / raw 51`，Cheapest 为 `—`。
- **单卡页**：11 张。H100 有 6 个 market、24 条 on-demand offers；A100 标 `sku_mismatch`，H100 标 `mixed`。每页含 KPI、市场切换、median + P25–P75 + cheapest 折线、offers、monthly、weekly index、crosscheck、来源与 JSON 下载。
- **Provider 详情页**：own 与 ext 分开，RunPod 的 own/ext 页面各自 fetch 对应切片。外部页固定展示 `GPU Economy · CC BY 4.0`、license 链接、source、`scraped_at`；fees 缺失写 `not published`，stopped 记录不标成当前报价。
- **Compare**：11 张卡可选，限 2–4 张，按共同有效周重定基为 100。表格新增 Weeks / Status；Weeks < 2 或末期滞后 ≥ 14 天标“覆盖不足，不可比较”，变化留空，不补零。B300 + GH200 显示该状态，GH200 不再出现 0.0% 的假变化。
- **Spread / Cheapest**：按 card × market × layer 分组，当前 **312** 个行/组。外部 median/P25–P75 先按 `MARKET_VIEWS` 过滤（community 只 instance、marketplace 只 floor、reserved 含 1y/3y），每个 provider 取最低价去重后再跨 provider 统计；own 与 external 分组独立。Card 下拉共 **78 项** = 11 张关键卡 + **66** 个外部非 11 卡 GPU + “全部卡”；外部非 11 卡显示纯文本和“外部参考 · 无单卡页”。页面 KPI 的 **1,082** 是 live + USD + 可映射（含 131 条 floor），不是 C 节的 962（live + 非 floor + USD）。页面明确标注 cheapest/dearest 是挂牌报价端点，不是成交价。
- **移动端**：390px 下对 7 个入口页做元素级检查，`documentElement`、`body` 与非表格容器均无横向溢出；宽表只在 `.table-wrap` 内滚动。

### E. 修复记录

Critic R1 结论为 FAIL（1 个 P1），修复后 Critic R2 结论为 PASS。随后 Challenger R1 又指出 spread 外部口径的 P1 和若干 P2；修复后 Challenger R2 未击穿，Critic R2 保持 PASS。

#### Critic R1 → R2

- **P1 图表把 null 画成 0**：`CC.lineChart` 现在把 `null/undefined/""/空白字符串` 视为缺失值，不参与 y 轴和坐标计算；缺失区间断线，全缺失 series 显示空态。H100 Reserved、GH200 on-demand 不再出现 `$0.00` 假线。
- **390px 图表文字过小**：viewBox 宽度改为容器实际宽度（320–1000），390px 下坐标文字保持约 11px；resize 与隐藏 tab 显示时重绘。
- **providers USD 口径**：providers 页外部 cheapest 统一为 live + 非 floor + USD；spread/cheapest 则按 `MARKET_VIEWS` 把 marketplace floor 单独挂到 marketplace 组，不混入 community/on-demand，修复同一 provider 在不同页面出现语义不同的“最低价”。
- **外部 live/raw 语义**：列表页和详情页都实时计算 live 统计，`current_quotes` 只标为原始记录（含 stopped/非 USD）；0 live provider 不再显示成“当前 51 条报价”。
- **spread/cheapest 外部卡筛选**：Card 下拉从实际分组动态生成，覆盖 66 个外部非 11 卡 GPU；这些行不生成假卡页链接。
- **`out_dir` 越界**：`write_public_data(out_dir=...)` 的站点切片改为写入 `out_dir/data`，所有返回路径都在调用方指定目录内。
- **旧页面/旧 JSON 清理**：`write_site` 按当前 site-index slug 清理 `gpu/*.html`、`providers/*.html`；`write_site_data` 清理 `data/cards`、`data/providers` 的旧 JSON。数据收缩时不会留下可访问的 stale 页面。
- **动态计数**：smoke 与 site 测试的页数、行数、offers 数改为从 `site-index.json`、`crosscheck.json`、卡片切片和外部报价动态推导，避免日常刷新把合法数据变化判成失败。
- **空市场与状态色**：0 家自有 provider 的 market 显示“无自有报价”，不再标“样本偏薄”；coverage 色调在 landscape 与卡页对齐。

#### Challenger R1 → R2

- **P1 spread 外部口径**：外部 median/P25–P75 改为按 `MARKET_VIEWS` 过滤（community 只 instance、marketplace 只 floor、reserved 含 1y/3y），再对每个 provider 取最低价去重，最后跨 provider 计算。核对值（median / provider 数）：A100 on_demand `1.765 / 48`、RTX 5090 community `0.47 / 2`、RTX 4090 community `0.25 / 2`、B300 spot `5.035 / 6`，与 crosscheck / landscape 一致。

- **Compare 覆盖状态**：新增 Weeks / Status 列；Weeks < 2 或末期滞后 ≥ 14 天标“覆盖不足，不可比较”，变化留空。B300 + GH200 显示该状态，GH200 不再显示 0.0% 的假变化。
- **Staging data 契约**：`write_public_data(out_dir)` 只写数据：`out_dir/data` 补齐 `prices.json`、`crosscheck.json`、`gpus.json`、`providers.json`、`site-index.json` 等运行切片；页面必须再调用 `write_site(out_dir)` 才会生成，完成后 staging 页面才可直接 fetch。
- **Landscape / providers 展示**：空市场改“无自有报价”；Weekly idx 只对 on-demand 显示；providers 的 Live coverage 拆成 own key cards / ext GPU ids，并注明单位不同、不可直接比较。
- **清单与清理**：`manifest.json` 增加 `site-index`、`cards`、`providers`、`external/prices`、`external/providers`；主页面 favicon 移除 `data:,` 空图标，只保留相对 `./favicon.svg`（以最终 build 为准）；`price-index` 旧切片会 prune。

### G. 已知限制

1. 单卡页仍只有 11 张关键卡；外部非 11 卡 GPU（如 A40、MI325X）只在 spread/cheapest 和 104 个 ext provider 的报价明细中出现，不为它们生成单卡页。
2. 外部 121 家“有记录”provider 生成详情页，127 家摘要全量保留；6 家 0 记录 provider 不生成页面。
3. 外部报价原始 1,399 条；962 是 live + 非 floor + USD 的严格非 floor 口径，1,082 是 spread/cheapest 页面 KPI 的 live + USD + 可映射口径（含 131 条 floor，排除 11 条不可映射非 floor）。页面保留 stopped/非 USD 原始记录并在状态列标明，不能把 raw 数当当前覆盖。
4. `providers.html` 为了计算 live coverage/live quotes/cheapest 仍会拉取约 587KB 的 `external/prices.json`，移动端首屏有优化空间；可在 site-index 预计算后去掉全量拉取。
5. 所有页面依赖静态 HTTP；`file://` 直接打开会 fetch 失败。
6. 历史月会随底表回填重算，不是不可变快照；外部数据固定在 `2026-11-03` 快照，边界与 P2-2 一致。
7. 卡页的 monthly/weekly/crosscheck/offers 由浏览器渲染；禁用 JS 时只显示服务端渲染的摘要和 KPI。
